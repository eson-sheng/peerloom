# 房间与媒体容量

默认每间房 12 人，所有成员均可开启麦克风，不占用实时媒体席位。房主禁用成员媒体权限时仍会停止其语音和内容共享。

默认 6 个实时媒体席位，允许六位成员同时共享屏幕或摄像头。每位成员同时只能发布一路内容（屏幕、摄像头、同播三选一），语音独立保留。同播占用发起者的实时媒体席位，全房同时仅允许一位同播者；其他席位仍可共享屏幕或摄像头。暂停同播不释放控制权，结束、退出席位、被禁用媒体权限或离开房间会释放。

前六位加入者自动获得媒体席位，其他成员可语音、观看和协作；已有成员释放视频席位后可申请。退出视频席位不会关闭麦克风。

在服务器配置文件或环境变量中设置：

```dotenv
PEERLOOM_MAX_ROOM_MEMBERS=12
PEERLOOM_MAX_MEDIA_SEATS=6
```

两项必须为正整数，媒体席位不能超过房间人数。重启服务器后生效；前端人数和席位显示使用服务端下发的上限。当前为 WebRTC mesh，增大人数会增加客户端连接数和带宽消耗。

部署时需同时更新服务端及前端，同播发起请求新增 `playback: true` 标记，由服务端在创建流时原子地保留同播控制权。

生产构建需使用 `-ldflags="-X main.mode=prod"`，只加载 `peerloom.config.local`、`peerloom.config` 及用户/系统配置，忽略开发配置。开发模式优先读取 `peerloom.config.development.local`、`peerloom.config.development`，未设置的值再从通用配置读取。进程环境变量优先于所有文件。仓库的开发配置不重复设置人数，默认继承 `peerloom.config`。

菜单显示服务端房间消息中的真实上限；修改配置后需要重启服务。Go 可执行文件内嵌前端，发布时应先构建 UI 再重新构建服务端，仅替换 UI 文件不能更新已编译的程序。
